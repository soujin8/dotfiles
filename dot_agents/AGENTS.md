# 個人共通の作業方針

## 進め方と完了条件

- 依頼の目的、対象、完了条件に合わせて作業する。実装の依頼は、必要な動作確認と今回の変更による不具合の修正まで進める。
- 小さな変更はそのまま実行する。複数の設計判断や依存関係がある場合は短い計画を共有し、前提が変わったときに更新する。ステップ数だけで Plan モードや仕様書の作成を必須にしない。
- 既存コードや資料で分かることは調べる。結果を大きく左右し、調査でも解決できない不明点だけ質問する。仮定で進められる箇所は仮定を明記する。
- 独立した調査や検証が並行して進められる場合にサブエージェントを使う。対象、問い、完了条件を渡し、結論に必要な根拠を確認する。

## 変更と確認の範囲

- 依頼に必要な変更を、既存の構成に合わせて行う。無関係なリファクタリングや既存の CI 失敗の修正まで広げない。
- 検証は変更の影響に合わせる。挙動の変更には関連テストや型チェックなどを選び、文書だけの変更には内容、リンク、形式の確認を行う。
- 確認できたこと、実行できなかった検証、残る問題を区別して報告する。検証が通った後の反復や全体テストへの拡張は、新たな変更、失敗、未解決の懸念がある場合に行う。
- すでに依頼された範囲の調査、編集、確認、修正は、各工程で承認を取り直さず進める。公開、送信、データ削除などは、今回の依頼や既存の許可に含まれるかを確認する。

## 知識と指示の管理

- 過去の判断が影響する作業で、関連する履歴や記録を参照する。全タスクで資料や lessons を一括して読まない。
- 訂正を受けたときは、将来も有効な好み、業務ルール、設計判断を適切な既存資料に反映する。一度限りの指示から常時適用のルールを増やさない。
- 個人共通の設定・スキルは chezmoi ソースを編集し、対象を指定して反映する。プロジェクト固有の制約は、そのプロジェクトの AGENTS.md や該当スキルに置く。
- 依頼文や保存プロンプトを作成・見直すときは、`~/.agents/task-prompts.md` の該当するひな形を参照する。
