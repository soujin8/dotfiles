# Wiki のページ形式と更新方法

## 保存先

| ディレクトリ | 内容 |
| --- | --- |
| `domain/` | 業務上の概念 |
| `rules/` | 業務ルール・制約 |
| `design/` | 設計判断と理由 |
| `specs/` | API・データ・画面の仕様 |
| `troubleshooting/` | 再利用できる調査・解決の知見 |

INDEX.md と関連ページを確認し、該当ページがあれば更新する。なければ該当カテゴリに `kebab-case.md` を作る。必要なディレクトリと INDEX.md は、最初の書き込み時に作成する。

## ページ例

```markdown
---
title: 満室想定の距離バリデーション
category: domain
updated: 2026-04-27
repos:
  - sumasate-api
related:
  - specs/assessment-api.md
---

# 満室想定の距離バリデーション

## 概要

対象と結論を短く書く。

## 詳細

確認できたルール、適用条件、根拠を書く。

## なぜこうなっているか

確認済みの背景や経緯を書く。根拠がなければ「背景未確認」と明示する。

## 関連

- 関連ページや資料へのリンク
```

`updated` は更新日。`repos` は対象リポジトリ名、`related` はwiki内の相対パスで、該当しなければ省略できる。大きな方針変更では、以前の判断が覆った理由と時点が追えるように残す。

## コード参照

複数リポジトリを横断するため、本文の参照は `<repo-name>:<path>:<line>` またはGitHubのコミット固定リンクを使う。`repos` が一つでも、本文のリポジトリ名は省略しない。複数リポジトリの説明が続く箇所は対象の切り替わりを明示する。

## INDEX.md

カテゴリ別の見出しと、一行のリンク・説明を並べる。新規作成時に追記し、タイトルやパスを変更したらリンクも直す。

```markdown
# Wiki Index

## domain

- [満室想定の距離バリデーション](domain/full-occupancy-distance.md) — 査定時に同等物件の距離をどう絞るか
```

コード構成の転記、短期のtodo、個人の応答の好みはwikiへ追加しない。業務知識として意味のある仕様や判断の背景に絞る。
