# Pull Request Update

- 指定されたPRを優先し、指定がなければ現在のブランチに対応するPRを特定する。PRがなければその旨を伝える。作成も依頼されている場合は、その依頼に従って作成手順へ進める。
- PRメタデータ、現在の本文、実際のPR差分、リポジトリのテンプレートを読む。ローカルだけにある未公開の変更を、PRに含まれる変更として説明しない。
- 現在の問題と変更後の挙動を先に述べる。既存の重要なメモ、経緯、関連リンク、チェックリストの状態を保持し、古くなった説明を更新する。推測で背景や検証結果を埋めない。
- テンプレートの必須項目を守り、規模に合った本文にする。独立した「変更の意図」見出しは、テンプレートや説明に必要な場合に使う。
- 「本文を更新して」という依頼は更新の許可として扱い、本文案の承認を取り直さない。「案を作って」なら案の提示までとする。変更対象や必須の仕様が未確定なら、本文を準備したうえでその点だけ確認する。
- 本文を実際の改行で一時ファイルに書き、`gh pr edit <PR> --body-file <file>` で反映する。反映後はPR本文を読み返し、PRへのリンクと変更の要点を伝える。
